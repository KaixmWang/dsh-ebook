# 读书使我更文艺

「读书使我更文艺」这句话，我大概说过八百遍。

每次说的时候都是同一个场景：有人问我周末干嘛，我说看书。其实那个周末我在床上躺了两天，手机屏幕的光照着一张浮肿的脸。

但话说回来，我是真想读的。

问题从来不在「想不想」，在「书到不了手上」。你想读的那本，国内没引进；引进的版本，绝版了；闲鱼上有人挂，价格像是他知道你有多想要。于是你打开搜索引擎，进入那个所有读书人都心照不宣的地下世界，开始一轮漫长的体力活：搜、翻页、点链接、等下载、断掉、重来、下下来是个扫描版 PDF、复制不出一行字。

文艺感毁在第二步半。

## 一、我想要的其实不是读书，是书在我手上

去年开始，我一天到晚泡在 DeepSeek Harness 里干活。既然跟它说的话比跟老婆说的还多，那不如让它顺手把书也弄进来。

于是有了 `dsh-ebook`。

它干的事很不文艺：**搜书 → 取书 → OCR → 翻译 → 推送微信读书**，一条链缝死。

解析完，产出两份东西。一份 Markdown 分章正文，给模型读；一份 EPUB 加封面书架，给我读。

前者决定这本书能不能被讨论，后者决定我愿不愿意打开它。两个都要，才叫完整——只给 AI 的那种，我不承认它是书库。

## 二、五个工具

插件往会话里递了五个工具，命名克制得像程序员写的备注：

- `ebook_search`：聚合检索，epub 优先、重复条目合并、超大合集降权
- `ebook_fetch`：下载或读本地文件 → 解析 → 补封面简介 → 自动 OCR → 切章
- `ebook_translate`：按章翻译，逐章落盘
- `ebook_read`：按章读书给模型，带字数预算和 `nextStart`
- `ebook_library`：书架状态，章节数、字数、OCR 与翻译进度、OPDS 地址

书源三条腿：LibGen、Z-Library、Internet Archive。中文书名直接搜，不用先把自己翻译成英文再搜。

取书两条路，都很直白：

```
ebook_search → 拿 md5 + source → ebook_fetch
ebook_fetch({ path: 'D:/books/x.pdf' })
```

## 三、被 LibGen 教育过的人

我必须承认，取书这一层，是我被教育之后才做厚的。

单镜像取书在 LibGen 上的失败率高得离谱：镜像抽风、下载 key 过期、服务器传到一半断连、慢到你以为它死了。我第一次写的时候很天真，给下载设了个全局超时——听起来很规范，实际上是把「慢」和「死」当成了一回事。慢速传输被我亲手掐死，然后我对着日志骂网络。

后来改成 **stall guard**：不设全局超时，只有连续 45 秒没有新字节才判死。慢的可以一直活，真死了才死。

其余几层是：

- **镜像池**：从 shadowlibraries 权威目录拉实时镜像，缓存 24 小时
- **延迟探测**：下载前并发探一遍，按实际延迟排序，不盲试第一个
- **失败冷却**：超时 / 5xx / 429 冷却 45 秒，403 / 404 本轮直接摘除
- **启动重试**：拿不到第一个字节就退避重试，而且每次重新解析直链——镜像发的一次性 key 会过期，这点很坑
- **断点续传**：中断保留 `.part`，重下用 `Range` 接着来
- **完整性校验**：下完比 MD5，返回 HTML 错误页会被识别出来丢掉

这七层加起来不好看，但好用。**大部分「下载失败」不是网络问题，是写下载器的人对失败理解得太浅。**

## 四、扫描件里的字

扫描版 PDF 是 AI 阅读的头号敌人。处理顺序是有尊卑的：

1. PDF 自带文本层，直接用 `pdfjs-dist` 提取，绝不渲染
2. 没文本层的页，`@napi-rs/canvas` 渲染成 PNG，2.2 倍缩放，上限 1700px
3. 交给视觉模型逐页认，提示词里约束了双栏顺序、页眉页脚剔除、竖排转换
4. 多页并发 3；某页返回空文本，同页重试一次再记失败

第三条是分水岭。模型不缺认字的能力，缺的是「这一页该怎么读」的排版常识。双栏的书，它能把左右两栏串成一句话，读起来像精神病写的。

`ocr` 三档：`auto` 只补没文本层的页、`force` 全本重做、`off` 关掉。**每页一次模型调用，按页计费**，所以我把 OCR 模型指到了一个便宜的视觉模型上。省钱这件事，我向来不装。

## 五、翻译最怕的不是慢

整本翻译最怕「跑到 80% 崩了，重来」。所以 `ebook_translate` 是逐章落盘、断点续跑，重跑自动跳过已译章，产出 `book.zh.md` 和 `book.zh.epub`。

还有个开关：「翻译交给子代理执行」。开了以后每章在独立会话里翻，可以多轮自查，代价是慢得让你怀疑人生；子代理挂了会自动回退到直接调用。

OCR 和翻译可以用两套不同的模型，只影响插件内部，不动我当前会话的模型。这点很重要——我不想为了看书把干活的模型换掉。

## 六、最后一公里

书弄进来了，人得能看见它。

侧栏多了个「书库」图标，点开是封面网格。一本书入库时，插件会把「值不值得读」的几个信号补齐：封面（EPUB 内嵌图 / PDF 首页 / 豆瓣候选，三级兜底）、简介、评分（微信读书优先，豆瓣兜底）。

一本只有文件名的书，在我脑子里是「资源」；有封面、有简介、有评分的，才是「一本书」。**文艺是被这些细节喂出来的**，虽然我承认这很像自我安慰。

推送微信读书走墨水屏端接口，COS 三段导入：取凭证 → 上传 → notify。有个细节我挺满意：如果这本书翻译过，点推送会先让你选「原书」还是「中文译本」，选完才推；只有一个版本就直接推，不打断你。

登录支持扫码，设置页点「显示二维码」，手机扫一下凭据自动存。也支持手填 `refreshToken` 和 `deviceId`——给那些习惯自己动手的人留的门。账号卡片还显示今日配额，比如「今日 4/10」，提醒你今天的额度已经花在了不该花的地方。

另外有个 **OPDS**，不占工具位，`opds.autoStart: true` 时插件一加载就起来。KOReader 之类的阅读器加上地址就能直接拉书。默认只听 `127.0.0.1`，要给手机用才改 `0.0.0.0`——没鉴权的东西，我不好意思让它裸奔在局域网上。

Kindle 推送我没做。生成 `book.epub` 自己发到 `@kindle.com` 就行，这个缺口我不打算补。

## 七、几处不太显眼的取舍

- **零外部工具依赖**：EPUB 的解析和生成用自写的 ZIP 读写器（`src/zip.js`，只依赖 `node:zlib`）。装个插件不该顺带装一堆二进制。
- **Z-Library 走 eAPI**：网页端有 DiamWall，要跑 JavaScript 才过；`/eapi/` 是官方客户端的 JSON 通道，实测不走那层保护。这不是绕过，这是走正门。
- **探接口，不探首页**：首页能开但搜索被挡太常见了，探首页只会给你假阳性。所以「书源可达性」探的是实际接口，LibGen 每个镜像单独列。
- **默认读系统代理**：Node 的 fetch 不会自动走系统代理，所以默认去读 Windows 的代理设置（Clash、V2Ray 之类），也能用 `proxy` 项覆盖。这个坑我踩过，不提了。
- **接口只挂本机**：`/dsh-ebook/api` 只接受回环或同源请求，写操作还要 `x-dsh-ebook: 1` 请求头——跨站请求带它会触发预检，于是被挡住。密码、cookie、refreshToken 存在本机，接口只回「有没有存过」，不回内容。

## 八、装起来

以 DSH bundle 分发，装完重启。在 profile 目录里：

```bash
pnpm add https://github.com/KaixmWang/dsh-ebook/releases/download/v0.5.2/dsh-ebook-0.5.2.tgz
```

然后把 `dsh-ebook` 加进该目录 `package.json` 的 `dsh.profile.bundles`：

```json
{ "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-ebook"] } } }
```

也可以直接从仓库装（会拉整个仓库）：

```bash
pnpm add github:KaixmWang/dsh-ebook
```

装好侧栏出现「书库」，设置在该插件详情页里，不占 DSH 通用设置页的位置。MIT 许可，源码全 ESM、无构建步骤。

## 九、以及它做不到的

- Z-Library 要账号，额度用完会明确告诉你，不装死
- OCR 质量看你配的视觉模型，认不出的字用 `▢` 占位，失败页码记进 `meta.json`
- mobi / azw3 只登记不解析，要正文请选 epub 或 pdf
- 直连境外书源，通常需要代理

诚实列出来的限制，比一句「已完美支持」体面。

## 十、结尾

按本站的分类，这篇大概该归到「先做个垃圾出来」。

书库里现在躺着的书，比我读完的多得多。这件事我没办法用插件解决——它能让书一秒到手上，也能让书一秒进书库，然后永远躺在那里，封面很好看，简介齐全，评分 9.1。

所以「读书使我更文艺」到底成不成立，我至今没有答案。

但至少现在，我说我在看书的时候，手机屏幕上真的有一本书。

翻不翻是另一回事。
