# 读书使我更文艺

「读书使我更文艺」这句话，我大概说过八百遍。

每次说的时候都是同一个场景：有人问我周末干嘛，我说看书。其实那个周末我在床上躺了两天，手机屏幕的光照着一张浮肿的脸。

但话说回来，我是真想读的。

问题从来不在「想不想」，在「书到不了手上」。想读的那本，国内没引进；引进的版本，绝版了；闲鱼上有人挂，价格像是他知道你有多想要。于是你打开搜索引擎，进入那个所有读书人都心照不宣的地下世界，开始一轮体力活：搜、翻页、点链接、等下载、断掉、重来、下下来是个扫描版 PDF、复制不出一行字。

文艺感毁在第二步半。

## 所以我做了个插件

`dsh-ebook`，装在 DeepSeek Harness 里的电子书库。四个字概括：**搜书、取书、读书**。

- 搜书：LibGen、Z-Library、Internet Archive 三个书源一起搜，中文书名直接搜。
- 取书：下回来解析，EPUB 和 PDF 都吃，扫描版也能认字，顺便补上封面、简介、评分。
- 读书：切成章节，一份 Markdown 给 AI 读，一份 EPUB 加封面书架给我读。

前者决定这本书能不能被讨论，后者决定我愿不愿意打开它。只给 AI 的那种，我不承认它是书库。

还有翻译和推送。翻译是逐章翻，翻到一半崩了能接着跑。推送是一键推到微信读书，手机和墨水屏上都能接着看。

## 三件我比较得意的事

**一、下载不容易失败。**

单镜像取书在 LibGen 上失败率高得离谱：镜像抽风、下载 key 过期、传到一半断连。我第一次写的时候很天真，给下载设了个全局超时，听起来很规范，实际上是把「慢」和「死」当成了一回事，慢速传输被我亲手掐死，然后我对着日志骂网络。

后来改成只看「连续 45 秒有没有新字节」。慢的可以一直活，真死了才死。再加上镜像池、延迟排序、失败冷却、断点续传、MD5 校验，才算能用了。

**二、扫描件能重新变成字。**

有文本层的 PDF 直接提取，不渲染。没有的，把每页渲染成图片交给视觉模型认。提示词里特意交代了双栏不要串行、页眉页脚不要混进正文、竖排要转过来——模型不缺认字的能力，缺的是「这一页该怎么读」的排版常识。双栏的书它能把左右两栏串成一句话，读起来像精神病写的。

**三、翻译不怕崩。**

逐章落盘，重跑自动跳过已译的章节。整本翻译最怕的不是慢，是跑到 80% 崩了重来。

## 界面

侧栏多了个「书库」图标，点开是封面网格。一本书进来时，封面、简介、评分都会自动补齐，缺了可以手动重取。详情页能打开文件、换封面、删除、推到微信读书。

一本只有文件名的书，在我脑子里是「资源」；有封面、有简介、有评分的，才是「一本书」。**文艺是被这些细节喂出来的**，虽然我承认这很像自我安慰。

顺带做了个 OPDS，KOReader 之类的阅读器加个地址就能直接拉书。默认只听本机，要给手机用才放开——没鉴权的玩意儿，我不好意思让它裸奔在局域网上。

## 装起来

```bash
pnpm add https://github.com/KaixmWang/dsh-ebook/releases/download/v0.5.2/dsh-ebook-0.5.2.tgz
```

再把 `dsh-ebook` 加进 profile 的 `package.json` 的 `dsh.profile.bundles` 里，重启。侧栏出现「书库」就成了。MIT，源码全是 ESM，没有构建步骤。

## 它做不到的

Z-Library 要账号，额度用完会明确告诉你，不装死。mobi 和 azw3 只登记不解析，要正文请选 epub 或 pdf。直连境外书源，通常还得挂代理。Kindle 推送我没做，生成 EPUB 自己发到 `@kindle.com` 就完了。

## 结尾

按本站的分类，这篇大概该归到「先做个垃圾出来」。

书库里现在躺着的书，比我读完的多得多。这件事插件解决不了——它能让书一秒到手上，也能让书一秒进书库，然后永远躺在那儿，封面很好看，简介齐全，评分 9.1。

所以「读书使我更文艺」到底成不成立，我至今没有答案。

但至少现在，我说我在看书的时候，手机屏幕上真的有一本书。

翻不翻是另一回事。
